Esercizio: Uso di Git per Gestire il Codice

Obiettivo: Imparare ad utilizzare i comandi Git di base (git pull, git push, git commit) per testare il flusso di lavoro in un repository locale senza dover condividere il progetto con altri studenti.

Descrizione: Ogni studente lavorerà su una propria copia del repository, testando le operazioni di commit, pull e push.

Procedura

  1. Creazione del repository su GitHub

    Crea un nuovo repository pubblico su GitHub, chiamato my-todo-list. Aggiungi una descrizione breve e crealo vuoto (senza file README, .gitignore, etc.).

  2. Clonazione del repository

    Clona il repository vuoto appena creato sul tuo computer locale con il comando:

    git clone https://github.com/tuo-username/my-todo-list.git

    Naviga nella cartella del progetto:

    cd my-todo-list

  3. Creazione di un file di lavoro

    Crea un file chiamato index.html e scrivi un semplice codice HTML che includa una lista di cose da fare (to-do list).

    Aggiungi il file al repository con il comando:

    git add index.html

  4. Commit delle modifiche

    Esegui il commit delle modifiche con un messaggio descrittivo, come:

    git commit -m "Aggiunto file index.html con struttura di base"

  5. Push del codice sul repository remoto

    Esegui il push delle modifiche sul repository GitHub:

    git push origin main

    Dopo aver eseguito il push, verifica su GitHub che il file index.html sia stato caricato correttamente.

  6. Aggiornamenti locali (modifica del codice)

    Apporta una modifica al file index.html (ad esempio, aggiungi un nuovo elemento alla lista).

    Aggiungi e committa le modifiche:

    git add index.html
git commit -m "Aggiornata la lista con nuovi elementi"

  7. Esegui un pull

    Simula l’arrivo di modifiche nel repository remoto (anche se sei l’unico che lavora sul repository, puoi fare delle modifiche in GitHub direttamente e poi fare un pull).

    Dopo aver fatto una modifica su GitHub, esegui un git pull per recuperare le modifiche:

    git pull origin main

  8. Risoluzione di conflitti (opzionale)

    Modifica lo stesso file index.html sia localmente che su GitHub, quindi prova a fare un git pull. Git ti mostrerà un conflitto che dovrai risolvere manualmente.

    Dopo aver risolto il conflitto, committa le modifiche risolte.

Domande di verifica

  1. Cosa fa il comando git push?
  2. Quando è necessario fare un git pull?
  3. Cosa succede se hai delle modifiche locali non commesse quando esegui un git pull?
  4. Cosa significa un conflitto di merge e come si risolve in Git?
  5. Qual è la differenza tra il comando git add e git commit?
